# Iface.Oik.DbBridge

Программа обмена телеметрией между Сервером «ОИК Диспетчер НТ» и сторонними базами данных. Поддерживается работа с СУБД PostgreSQL, MySQL и Microsoft SQL Server. 

Программа может работать как внешняя задача Сервера «ОИК Диспетчер НТ» или автономно на любом удаленном компьютера.

## Аргументы запуска программы

```
./Iface.Oik.DbBridge сервер_тм /h=компьютер /u=пользователь_оик /p=пароль_оик /db=параметры_базы_данных /period=период_исполнения /offset=смещение_исполнения /cfg=файл_sql_запросов
```

### Описание аргументов запуска

`/period=…`

Период исполнения, в секундах, по умолчанию 10 секунд. Например, если задано 10 секунд, то импорт/экспорт будет запущен ровно в 0, 10, 20, 30, 40 и 50 секунд каждой минуты.

`/offset=…`

Смещение исполнения, в секундах, по умолчанию 0. Например, если период задан 10 секунд, а смещение - 1 секунда, то импорт/экспорт будет запущен ровно в 9, 19, 29, 39, 49 и 59 секунд каждой минуты.

```
/db=тип,компьютер,порт,база,пользователь,пароль
```

Параметры базы данных, где тип — один из:
- PGSQL — PostgreSQL,
- MYSQL — MySQL,
- MSSQL — Microsoft SQL Server.

Примеры корректного задания строки соединения с базой данных:
```
/db=PGSQL,10.0.0.1,5432,dbname,user,password
/db=MYSQL,localhost,3306,dbname,user,password
/db=MSSQL,192.168.88.100,1433,dbname,user,password
```


### Пример аргументов запуска автономной программы

```
./Iface.Oik.DbBridge TMS /h=10.0.0.2 /u=user /p=password /period=30 /offset=1 /db=PGSQL,10.0.0.1,5432,dbname,user,password
```

### Пример аргументов запуска внешней задачи

```
/period=60 /db=MYSQL,localhost,3306,dbname,user,password
```

## Файл SQL-запросов

Команды импорта и экспорта данных определяется в файле SQL-запросов.

По умолчанию программа ищет файл в подкаталоге `"sql"` с именем `"config.sql"`.
Задать другой путь к файлу можно с помощью аргумента запуска `/cfg=путь_к_файлу`

Файл может содержать сразу множество запросов, разделённых точкой с запятой.


### Импорт из базы данных в сервер «ОИК Диспетчер НТ»

Используется запрос `SELECT`, который должен вернуть пять колонок в заданном порядке: Тип телеметрии, Канал, КП, Объект, Значение. 

Тип телеметрии должен быть `#TC` (для сигналов) или `#TT` (для измерений).

#### Пример

Для таблицы с заданными колонками и значениями

| type | ch | rtu | point | value   |
|------|----|-----|-------|---------|
| #TC  | 0  | 1   | 1     | 1       |
| #TT  | 0  | 1   | 1     | 3.14    |
| #TT  | 0  | 1   | 2     | 2.71828 |

при вызове следующей команды

```
SELECT type, ch, rtu, point, value 
FROM table_name;
```

в сервер будут записаны следующие значения:
- для сигнала с адресом #TC0:1:1 будет записано значение 1
- для измерений с адресами #TT0:1:1 и #TT0:1:2 будут записаны значения 3.14 и 2.71828 соответственно

### Экспорт из сервера «ОИК Диспетчер НТ» в базу данных

Используются все остальные запросы, текст будет обрабатываться препроцессором, который исполняет текст между знаками %. 

Так выполняются выражения на языке ЯРД, допустимые в поле "выражение" телепараметров.

Описание языка ЯРД приведено в [документации сервера «ОИК Диспетчер НТ»](https://iface.ru/webdocs/oikserver3/prilozhenie_b__opisanie_yazyka_yard.html) 

#### Пример

Для таблицы с заданными колонками

| time                | pa    | pb    | pc    |
|---------------------|-------|-------|-------|

при вызове следующей команды

```
INSERT INTO table_name
(time, pa, pb, pc)
VALUES
(NOW(), '%#TT20:1:3%', '%#TT20:1:4%', '%#TT20:1:5%');
```

в базу данных будут записаны значения измерений с адресами #TT20:1:3, #TT20:1:4 и #TT20:1:5. После нескольких занесений таблица может выглядеть, например, так:

| time                | pa    | pb    | pc    |
|---------------------|-------|-------|-------|
| 2025.04.23 08:13:00 | 17.83 | 15.21 | 18.05 |
| 2025.04.23 08:13:10 | 16.91 | 15.22 | 17.91 |
| 2025.04.23 08:13:20 | 17.22 | 16.08 | 18.05 |

### Примеры файлов SQL-запросов
Примеры файлов SQL-запросов доступны в каталоге `"sample_sql"` в архиве установки.
